# Measure answer accuracy with GLM 5.3 Flash as the reader

v1 scored retrieval only; whether the reader turns retrieved text into right answers was left open. A chunking can retrieve the labelled spans and still hand the reader text it uses badly, and v2's question - routing versus indexing - is about the system's answers, not its recall tables, so every contender must be read, not only the eventual winner. The reader itself must not become a variable: a different model or prompt per contender would swamp differences of a few hundredths.

So answer accuracy runs with GLM 5.3 Flash as the reader and one fixed prompt, written before any result: answer from the context only, briefly, with short answers asked for on Natural Questions precise questions; thinking off, temperature 0. It reads a 1,000-question sample, 500 per dataset, drawn by document, and every setup goes through it: each contender, the oracle router and a no-retrieval floor. Contextual prefixes are used for search only and do not count against the token budget; the reader receives the original chunk text. Answers are scored with the datasets' standard answer metrics, with a model-graded check on 300 questions that the standard scores track correctness. The alternatives were reading only the winner, which leaves the retrieval-to-answer link unmeasured exactly where the trade-offs sit; a larger, slower reader, when any deterministic model held fixed serves the comparison; and model-graded scoring as the primary metric, which is less comparable across datasets than their standard metrics, so it is kept as a check.

## Amendment (2026-10-17): a local reader, three setups, and a grader through the `claude` command-line tool

The decision above stands except for the reader, the setups and the grader, which change as follows; the original text is kept as it was decided.

- **Reader.** GLM 5.3 Flash cannot be called in batch from the experiment's code under the terms of the plan it was to run on, and a pay-as-you-go account is out of scope. The reader is therefore the local Qwen3-8B: 4-bit MLX weights (`mlx-community/Qwen3-8B-4bit`, revision `545dc4251c05440727734bcd94334791f6ab0192`, the model that wrote the context prefixes), thinking switched off in its chat template, greedy decoding, at most 256 new tokens, one prompt at a time, with the same fixed prompt for every setup. "Thinking off, temperature 0" holds as written.
- **No-retrieval floor.** It uses the closed-book variant of the prompt: the same template without the context section and without "from the context only". With the literal prompt and an empty context the reader could only refuse, so the floor would measure refusals instead of what the reader knows.
- **Setups.** Only section-aware, the oracle router and no retrieval are read, on the same 1,000-question sample. No contender reached the retrieval bar (see the amendment to ADR 0008), so reading every contender no longer decides anything; the stage now asks whether better retrieval moves answers.
- **Model-graded check.** 300 answers: 50 questions per dataset (Natural Questions half precise, half context), seeded, times the three setups. Each is graded pass or fail through the `claude` command-line tool in headless mode, with no tools and on a subscription login, never a paid API, using a grader prompt committed before any answer existed. The check reports how often the standard answer score and the grader agree.
