# Measure answer accuracy with GLM 5.3 Flash as the reader

v1 scored retrieval only; whether the reader turns retrieved text into right answers was left open. A chunking can retrieve the labelled spans and still hand the reader text it uses badly, and v2's question - routing versus indexing - is about the system's answers, not its recall tables, so every contender must be read, not only the eventual winner. The reader itself must not become a variable: a different model or prompt per contender would swamp differences of a few hundredths.

So answer accuracy runs with GLM 5.3 Flash as the reader and one fixed prompt, written before any result: answer from the context only, briefly, with short answers asked for on Natural Questions precise questions; thinking off, temperature 0. It reads a 1,000-question sample, 500 per dataset, drawn by document, and every setup goes through it: each contender, the oracle router and a no-retrieval floor. Contextual prefixes are used for search only and do not count against the token budget; the reader receives the original chunk text. Answers are scored with the datasets' standard answer metrics, with a model-graded check on 300 questions that the standard scores track correctness. The alternatives were reading only the winner, which leaves the retrieval-to-answer link unmeasured exactly where the trade-offs sit; a larger, slower reader, when any deterministic model held fixed serves the comparison; and model-graded scoring as the primary metric, which is less comparable across datasets than their standard metrics, so it is kept as a check.
