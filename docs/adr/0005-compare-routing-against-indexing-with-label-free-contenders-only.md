# Compare routing against indexing with label-free contenders only

v1 found routing headroom of about +0.13 retrieval recall for both embedders and cleared its gate, but a router that picks from the question's own text cannot be learned from labels: v1's per-question results carry labels, most corpora do not, and a method that needs labelled routing decisions would not carry to any corpus but the one it was trained on. v1 also showed that knowing only each question's type is worth +0.0000. And the headroom may not come from routing between chunkings at all: indexing one chunking better, by letting each chunk carry more of its surroundings, might capture the same gain without a router.

So v2 runs label-free contenders only, against section-aware, with v1's oracle router as the ceiling: search-all routing, confidence routing, late chunking on fixed 128- and 256-token windows, and contextual chunks on fixed 256-token windows. Learned routers are out: a classifier or fine-tuned model trained on v1's per-question results was considered and dropped, because labels do not exist for most corpora; so was a router that decides from the question alone, such as a zero-shot decision model picking a chunking from descriptions of them, which never sees the retrieved text and sits where v1's query-type signal already priced in at nothing. ADR 0002's gate was met, so routing stays in the comparison; what it competes against now is better indexing of one chunking.

## Amendment (2026-10-18): section-aware chunks with their titles join the contenders

The approved v2 plan adds one contender to the set above (issue 36): section-aware's own chunks, indexed with the dataset's own document and section title in front - the cheapest context enrichment, a header no model writes, used for search only exactly as a contextual chunk's prefix is. It stays label-free and judged against section-aware under ADR 0008's bar; everything else above stands.
